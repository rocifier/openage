# FVD rain rendering

FVD games display continuous rainfall over the battlefield.
Rain is a local GPU post-process, generated by
`assets/shaders/fvd_rain.frag.glsl`; it creates no simulation entities,
commands or replicated multiplayer state.

The screen renderer composites the scene in this order:

1. Skybox, terrain and world sprites.
2. The rainfall pass.
3. The world HUD and Qt Quick GUI.

This keeps units and terrain visibly wet and the interactive controls
legible. The effect starts as soon as FVD gameplay is active (including
solo games), stops in the multiplayer lobby and resumes in the next
match. Animation uses steady presentation time, so a paused simulation
does not produce large or discontinuous particle jumps.

## Appearance and tuning

The fragment shader draws three independent sheets of drops with
different apparent depths. Each sheet has its own column spacing,
row spacing, fall speed, horizontal wind, lean, width, population density
and opacity. The distribution is spatially continuous between frames;
new random drop positions are not created every frame.

The `rain_sheet` calls in `main()` control the three layers.
Adjust their numbers to tune density, wind and visibility. The
`wet_air`, `reflected_light` and `haze` values control the cold
storm tint. Changes to the fragment shader require restarting the
native renderer to load the updated source.

Rain is deliberately a screen-space weather overlay for this
experiment; it does not yet react to roofs, hit the ground with ripples,
produce rain audio, or alter gameplay visibility. It needs a visual
and performance check on a running native build, particularly at high
display resolutions.
